# 36界面修复与交付说明

本轮仅修改显示层，保留35认证实现。先在模拟器复现并提供截图，随后按用户要求构建36版ARM64包。运行验证使用同代码x86_64包，ARM64包另做内容、ABI、签名和对齐核验；本阶段未执行36实车运行验证，当前待验状态见 [状态清单](known-issues.md)。

## 歌单播放按钮

2376×936/API32模拟器复现：KnockoutButton布局240×72像素正常，实际背景/文字放大裁切。读取到其两张离屏Bitmap密度149 DPI，而应用资源240 DPI。原draw使用带自动密度缩放的drawBitmap重绘离屏结果。

最小修复：在创建离屏Canvas之前，让两张Bitmap的density与当前绘制Canvas一致。修改后两张Bitmap均为240 DPI，截图中的播放按钮完整，既有点击绑定保留。专辑详情页对照正常。

## 播放器左侧

修改AM++已有TabletSongColumnLayout：投放按钮与IosVolumeSliderView设为GONE，不保留触摸区域；隐藏音量条同时停止其可见页轮询。用系统安全区与“拖动条顶部到播放控制底部”计算居中偏移，统一应用到封面、文字、进度和播放控件。队列底部控件高度也不再保留音量行。

已在模拟器观察：两个入口隐藏；左侧内容下移；播放进度推进且MediaSession为PLAYING、无playerError；歌词可显示，队列切换完成后正常；收起播放器正常。没有声称听觉输出、ARM64实车或新登录验证。

## 菜单问题暂缓

用户报告实车首页、新发现等页面右上角菜单会弹到左侧。本次模拟器在首页、新发现、广播及切页重试时，设置菜单均位于右侧，未复现。旧式MENU键本次没有打开菜单，不能从该尝试得出位置结论。用户决定之后实车ADB排查；36没有新增菜单修复，也没有新增AM++配置入口。
