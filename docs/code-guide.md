## 如果只想读核心代码

先打开 [FinalAccount.java](../src/com/e8/auth36/FinalAccount.java)，按方法读，不必从第一行逐句看反射工具：

1. **route**：判断是不是需要适配的最终登录动作。普通页面和不匹配的动作继续走原逻辑。
2. **Action.invoke**：把这项工作交给后台线程，完成后通知原程序；失败也如实通知。
3. **Action.perform**：核心业务。调用原StoreAPI，检查真实账户，保存/转换账户，再完成音乐授权，最后返回原界面需要的结果。
4. **Await / Completion**：适配原程序的异步返回方式，不是另一套认证算法。

`Gb.b`、`e7.e`等短名字是7.0反编译后的混淆类名，不是缺失文件。它们由宿主APK提供，不能在这个仓库里直接点开。升级Apple Music后必须重新核对这些名字及接口。

需要更精确的字段与调用关系时，再看 [架构](architecture.md)。

## 以后出现Bug，从哪里开始

| 问题 | 先做什么 | 相关范围 |
|---|---|---|
| 登录最后失败 | 记录阶段、状态码、异常类型，不提交秘密正文 | FinalAccount + 原宿主认证 |
| 原账号/密码/验证码页面异常 | 查原页面与WebView；确认是否到完成动作 | 原7.0 UI，不能默认归因于adapter |
| 歌词、双栏、播放按钮、菜单位置 | 记录屏幕尺寸/最小操作步骤，核查AM++与布局补丁 | AM++、历史UI辅助；当前仓库未覆盖所有生产源码 |
| 页面卡住、点击没反应 | 先区分ANR/资源不足与业务错误 | 系统性能、主线程、WebView |
| 包太大或安装失败 | 核对ABI、ZIP压缩/资源对齐、签名 | repack.py与verify_apk.py |
| 已登录但播放/资料库异常 | 核对音乐授权、账户状态及续期 | 不以头像或首页出现证明授权成功 |

## 实际改动的顺序

先建Issue描述现象，再建分支修改，最后做对应验证。认证适配器可按 [构建说明](build.md) 编译，并用自备34/35包增量组装。页面与模块改动需要先补齐对应生产补丁，不能声称现在已能一键重建整个应用。

每次写清楚“改了什么、为什么、怎么测、还有什么没测”。GitHub源码工具检查通过不等于实车功能通过。具体提交约定见 [CONTRIBUTING](../CONTRIBUTING.md)。
